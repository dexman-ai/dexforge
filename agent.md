# agent.md: DexForge Coding Standards

This document captures core tenets for contributors working on dexforge, a zero-allocation, `#![no_std]` analytical inverse kinematics solver library.

## Core Invariants

Every contribution must preserve:
1. **Zero allocation**: No `Vec`, `Box`, `BTreeMap`, or use of Rust `std` heap.
2. **Deterministic execution time**: Every iterative routine has a hardcoded iteration ceiling for bounded worst-case execution time (required for real-time control loops).
3. **Mathematical faithfulness**: Results match the Python reference implementation within floating-point tolerance.

## Core Tenets for Rust Code

### `#![no_std]` Compliance
- No `std` imports except in `#[cfg(test)]` blocks.
- All data structures are fixed-size stack arrays or `nalgebra::SMatrix`.
- All loops carry hardcoded iteration ceilings.

Verify with: `cargo build --release --target thumbv7em-none-eabihf`

### Deterministic Execution Time
- Every numerical loop must have a hardcoded maximum iteration count.
- No unbounded recursion or dynamic branching on convergence.
- No randomized algorithms (e.g., Möbius fallback for ill-conditioned poses; use deterministic perturbation + `lm_refine` instead).

### Type Safety & Fixed-Size Semantics
- 3D vectors: `[f64; 3]` or `nalgebra::SVector<f64, 3>`
- 4×4 matrices: `nalgebra::SMatrix<f64, 4, 4>` or `[[f64; 4]; 4]`
- Configuration output: always `[Option<[f64; DOF]>; MAX_SOLUTIONS]`

### Numerical Stability
- FK verification tolerance: `1e-5` (Frobenius norm).
- De-duplication tolerance: `1e-3` per joint (modulo 2π via `wrap_to_pi`).
- Degeneracy threshold: `1e-12` for singularity detection.
- All tolerances declared as `const`, not hardcoded inline.

### Angle Representation
- All angles in radians.
- De-duplication uses `wrap_to_pi` (modulo 2π canonicalization).
- Example: `fn q_eq_mod(a: &[f64; 6], b: &[f64; 6], tol: f64) -> bool { a.iter().zip(b.iter()).all(|(ai, bi)| (wrap_to_pi(ai - bi)).abs() < tol) }`

### Forward Kinematics (FK)
- Every solution candidate must be FK-verified before returning.
- FK uses product-of-exponentials with baked screw axes and link transforms.
- Baked constants generated by Python helper scripts; never hardcoded FK transformations inline.

### Testing & Validation
Every driver must include `#[cfg(test)]` module:
- Include reference dataset via `#[path = "test_data.rs"]` macro.
- Test FK closure (q=[0; DOF] should match T_HOME to 1e-5).
- Test reference dataset match: loop through poses, assert joint-space agreement to 1e-5.
- For singular poses: FK residual `< 1e-5` and relaxed joint tolerance `< 1e-3`.

Run tests: `cargo test`

### Documentation
- Module-level docs (`//!`): Explain arm kinematics and equivalence to Python reference.
- Function docs (`///`): Describe arguments, return semantics, tolerance parameters.
- Constants: Include `SOLVER_NAME`, `SOLVER_TIER`, `EXPECTED_MS_MEDIAN`, `FLOP_BUDGET`, `DISPATCH_REASON` (mirrored from Python artifact).

### Code Style
- Format with `cargo fmt`.
- Use existing code as style reference; avoid over-commenting.

## Module Responsibilities

### `src/math/ssik_core.rs` — Generic Numeric Kernels
- **3-vector primitives**: `dot3`, `cross3`, `norm3`, `add3`, `sub3`, `scale3`, `rotate`, `rotation_matrix`
- **3×3 matrix operations**: `mat3_mul`, `mat3_transpose`, `mat3_vec`, `mat3t_vec`
- **Polynomial root-finding**: `quartic_roots` (companion-matrix via Francis QR), `cubic_roots`
- **Subproblem solvers**: `sp1_solve`, `sp3_solve`, `sp4_solve`, `sp5_solve`, `sp6_solve` (IK-Geo)
- **Raghavan-Roth elimination**: `rr_real_roots`, `rr_left_null_space`, `rr_pseudo_inverse`
- **Angle wrapping**: `wrap_to_pi` (modulo 2π deduplication)

**Constraint**: All routines are allocation-free, use fixed-size types, and carry bounded-iteration loops.

### `src/math/kinematics.rs` — Arm-Agnostic Kinematics
- **4×4 homogeneous utilities**: `eye_with`, `rot_homogeneous`, `mat4_mul`
- **2×2 matrix helpers**: `mat2_ata`, `vec2_mat2`
- **Pose residual norm**: `norm12` (Frobenius-norm of residual transformation)
- **Rigid-transform type**: `Transform` struct, `IDENTITY`, `compose`, `se3_inv`, `frob_diff`
- **Generic Levenberg-Marquardt refinement**: `lm_refine<const DOF, F>` (const-generic over degrees of freedom); `lm_refine6` is backward-compat wrapper

**Constraint**: Refinement loop has hardcoded maximum iterations (`LM_MAX_ITERS = 15`), initial/final damping factors, and convergence threshold.

### Per-Arm Drivers (`src/drivers/{arm}/ik_solver.rs`)
Each driver implements:
- **`fk(q: &[f64; DOF]) -> SMatrix<f64, 4, 4>`**: Forward kinematics using baked constants
- **`solve(tf: &SMatrix<f64, 4, 4>, ...) -> [Option<[f64; DOF]>; MAX_SOLUTIONS]`**: Main IK solver
- **Constants**: `DOF`, `MAX_SOLUTIONS`, `SOLVER_NAME`, `SOLVER_TIER`, `EXPECTED_MS_MEDIAN`, `FLOP_BUDGET`, `DISPATCH_REASON`, `BASE_LINK`, `EE_LINK`, `T_HOME`, `JOINT_LIMITS`
- **Tolerance policy struct**: `TolerancePolicy { fk_atol, dedup_atol }` with `DEFAULT` constant
- **`#[cfg(test)]` module**: Reference dataset via `test_data.rs`, validates FK closure and joint-space agreement

**Key patterns**:
- Mirror Python ssik artifact structure exactly.
- Call subproblem kernels from `ssik_core` (no reimplementation of complex numerics).
- FK verification after each algebraic solve: `frob_diff(compute_fk(&q), &target) < policy.fk_atol`
- De-duplication modulo 2π using `wrap_to_pi`.

## Translation Guidelines

For detailed translation guidance, refer to `codegen/translate_ssik_artifact.md` (critical for Python-to-Rust ports).

**Key boundary**: The `ssik_core` module contains all complex numerical kernels (eigenvalues, root-finding, matrix operations). Drivers should extract arm-specific constants and straight-line algebraic blocks, then wire them to `ssik_core` functions. Do NOT reimplement complex numerical routines.

## Build & Test

```bash
cargo test                                             # host tests
cargo build --release --target thumbv7em-none-eabihf  # embedded no_std
```

For Python bindings (dexforge-py):
```bash
cd dexforge-py
maturin build --release
pytest tests/
```

## PR Checklist

Before submitting a PR with new Rust IK code:
- [ ] Code compiles: `cargo build --release` and `cargo build --release --target thumbv7em-none-eabihf`
- [ ] All tests pass: `cargo test`
- [ ] No `unsafe`, no `Vec`/`Box`/`std` heap allocation outside `#[cfg(test)]`
- [ ] All loops have hardcoded iteration ceilings
- [ ] FK verification done for every solution candidate
- [ ] De-duplication uses `wrap_to_pi` modulo 2π
- [ ] Reference dataset in `test_data.rs` matches expected solutions to tolerance
- [ ] Documentation includes solver metadata constants
- [ ] Python helper scripts (`generate_<arm>_*.py`) are provided and tested
- [ ] Code formatting: `cargo fmt --check` passes
- [ ] No hardcoded tolerances; all thresholds use named constants
- [ ] NaN-producing operations (acos, asin, sqrt) have domain checks
