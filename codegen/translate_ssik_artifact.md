# Translating a `ssik` artifact into `ik_solver.rs`

Sub-prompt of [`new_driver.md`](new_driver.md) (Step 3). You are translating the
arm-specific Python IK artifact `drivers/<arm>/codegen/<arm>_ik.py` (generated
by `ssik`) into mathematically identical, allocation-free Rust in
`drivers/<arm>/ik_solver.rs`. It runs inside a 500–1000 Hz `#![no_std]`
real-time control loop. Write the files directly with your file tools.

## 1. Reference implementation

1. Run `python codegen/ssik_artifact.py inspect drivers/<arm>/codegen/<arm>_ik.py`
   to get `DOF`, `MAX_SOLUTIONS`, the solver family and the reference arm.
2. Use the reference arm's `ik_solver.rs` (and `codegen/generate_code.py`,
   `codegen/generate_test_data.py`) as the structural template: same function
   decomposition, same constant layout, same test module.
3. The reference drivers predate `dexhal` and import their own math copy
   (`crate::math::...`). Their algorithms and tests are valid; when copying,
   import the same items from `dexhal::math` instead (e.g.
   `use dexhal::math::ssik_core::{sp6_solve, wrap_to_pi};`,
   `use dexhal::math::kinematics::{lm_refine6, mat4_frob_diff};`).

## 2. The `dexhal::math` boundary (CRITICAL)

**Do not reimplement numerical kernels or copy them into the vendor crate.**
`dexhal::math` owns `ssik_core` (subproblems, SP6, Raghavan-Roth root finding,
wrapping), `kinematics` (LM refinement, pose differences), `postprocess`
(limits, dedup, seed ordering) and `tolerances` (`TolerancePolicy`).

- Extract only the **arm-specific constants** and **straight-line algebraic
  blocks** from the Python file and wire them to those kernels.
- Wherever the artifact calls `_sp6_runtime.solve`, `eliminate_q0_q1`,
  `lm_refine` or root-finding helpers, call the matching `dexhal::math`
  function (`ssik_core::sp6_solve`, `ssik_core::rr_real_roots`,
  `kinematics::lm_refine6`, ...). If a needed kernel is missing from `dexhal`,
  stop and report it instead of writing a local copy.
- **Möbius / `pinv` fallback:** do not transpile randomized Möbius transforms or
  `pinv` fallbacks for ill-conditioned eigenproblems. Follow the reference
  pattern: solve a deterministically perturbed pose (e.g. 0.1 mm offset) with
  `rr_real_roots` and snap back with LM refinement.

## 3. Compilation and type constraints

1. `#![no_std]`, `#![forbid(unsafe_code)]` crate: no `std`, no heap (`Vec`,
   `Box`, `BTreeMap`). Use `libm::{sin, cos, atan2, sqrt, fabs, ...}` — `f64`
   methods like `x.sin()` are unavailable in `core`.
2. Fixed-size types: 3-vectors as `[f64; 3]` or `nalgebra::SVector<f64, 3>`,
   poses as `dexhal::math::Pose` (`nalgebra::SMatrix<f64, 4, 4>`).
3. Results as `[Option<[f64; DOF]>; MAX_SOLUTIONS]`; take `DOF` /
   `MAX_SOLUTIONS` from `super::arm` (or re-declare identical constants).
4. Every iteration is bounded (`for _ in 0..MAX_ITER`); no `loop` / `while`
   without a hard ceiling.

## 4. Translation steps

1. **Constants.** Emit hardcoded geometry, axes, limits and offsets as Rust
   `const`s, or bake them with `codegen/generate_code.py` into `consts.rs` /
   `pq.rs` when the reference arm does. Keep floating-point noise; do not
   "simplify" geometry.
2. **Algebraic blocks.** Transpile the straight-line scalar blocks
   (`th14_x*`, `q6_x*`, `dinr_*`, SP3 boundary branches, ...) preserving the
   assignment order, to avoid accumulation drift against Python.
3. **Interface.** `arm.rs` (generated by `codegen/scaffold.py`) calls exactly:

   ```rust
   pub fn solve(
       target: &Pose,
       max_solutions: Option<usize>,
       q_seed: Option<&[f64; DOF]>,
       respect_limits: bool,
       allow_refinement: bool,
       policy: TolerancePolicy,
       refinement_max_iters: usize,
   ) -> [Option<[f64; DOF]>; MAX_SOLUTIONS]
   ```

   FK and the Jacobian come from `generated_kinematics`; do not add another
   public FK (an internal chain FK used on the refinement hot path is fine).
4. **Domain guards.** Every `acos` / `asin` / `sqrt` argument that can leave its
   domain is checked against the `policy` tolerances and the branch is skipped
   (`continue`), never `NaN` or a panic.
5. **Post-processing.** With `respect_limits`, drop solutions outside
   `JOINT_LIMITS`; with `q_seed`, order nearest-first; honour `max_solutions`.
   Use the `dexhal::math::postprocess` helpers like the reference arm does.
   Joint-lock (`jointlock.*`) solvers additionally hold the locked joint at
   the seed's value on a seeded solve (the reference arm's `seed_locked`):
   polish the seed and every sweep solution with the locked joint set to the
   seed's, keep the FK-verified results, and fall back to the 16-sample sweep
   only when none closes.

## 5. Tests

Add a `#[cfg(test)]` module at the bottom of `ik_solver.rs`, mirroring the
reference arm:

1. `#[cfg(test)] #[path = "test_data.rs"] mod test_data;` loads the dataset
   written by `codegen/generate_test_data.py`.
2. For every case, call `solve()` and assert each reference solution is matched
   (joint distance `< 1e-5`, wrapped) and that every returned solution closes FK
   (`< 1e-5`). Singular cases use FK closure `< 1e-5` and joint dedup `< 1e-3`.
3. Never loosen tolerances to make a test pass; fix the translation.

## 6. Per-arm helper scripts

Both live in `drivers/<arm>/codegen/`, load the sibling `<arm>_ik.py` (not
`ssik.prebuilt`), and write their output one directory up, next to
`ik_solver.rs`:

- `generate_test_data.py` (all arms) — scaffolded by `codegen/scaffold.py`;
  mirror the reference arm's polish / singular-case handling when it has one.
  It calls `codegen.ik_test_data.write_ik_test_data`.
- `generate_code.py` (arms with baked sub-chain geometry or Raghavan-Roth PQ
  matrices) — adapted from the reference arm; writes `../consts.rs` /
  `../pq.rs` and prints `wrote ...`. Declare the new modules in `mod.rs`.
